## 1. 项目用途与选择原因

Ruff 是一个用 Rust 编写的 Python 代码检查和格式化工具，个人开发者可以在提交前用它查代码，团队也可以把同一套规则加到 GitHub Actions 里。本次调研从官方文档里的两个常用命令入手，看看它们在提交代码前各自能查出什么。[Ruff 官方文档](https://docs.astral.sh/ruff/) · [课程大纲](https://github.com/USTB-SE-Course/OSSDT-26/blob/main/Syllabus.md)

比如，一个脚本原来用过 `json` 模块，后来删掉了相关逻辑，却还留着 `import json`。运行 `ruff check` 时，Ruff 会按 `F401` 规则指出这个未使用的导入。运行 `ruff format` 则会按统一的规则调整排版，例如整理缩进和换行。在 GitHub Actions 里可以用 `ruff format --check` 检查格式，发现需要格式化的文件时，命令会以非零状态退出，文件原样保留。至于脚本给定一份输入能否产生正确结果，还需要用 pytest 之类的工具验证。[代码检查](https://docs.astral.sh/ruff/linter/) · [F401 规则](https://docs.astral.sh/ruff/rules/unused-import/) · [格式化](https://docs.astral.sh/ruff/formatter/)

## 2. 开源许可证

Ruff 采用 MIT 许可证，允许复制、修改和再分发。比如，修改 Ruff 后把修改版打包给别人，仍应在分发的副本中保留原版权声明和许可声明。这个要求同样适用于只分发软件中实质性部分的情况。项目的 `LICENSE` 文件还列出了部分代码的外部来源及对应许可，复用这部分代码时也应查阅相应条款。[Ruff 的 LICENSE 文件](https://github.com/astral-sh/ruff/blob/main/LICENSE)

## 3. 维护与活跃情况

从发布看，Ruff 在 2026 年 11 月 19 日发布了 `0.17.6`，版本说明列出了多项修复，包括 `F823` 规则的一次漏报。这个规则会检查局部变量在赋值前就被引用的情况。修复前，如果函数后面给同一个变量赋值多次，某些本应报告的位置会被漏掉。[0.17.6 发布说明](https://github.com/astral-sh/ruff/releases/tag/0.17.6)

从协作看，对应的 PR #30524 在 11 月 18 日合并。贡献者给出了能触发漏报的代码例子，并补上测试。审查和合并记录都可以在同一个 PR 里查看。把这条 PR 和次日的发布说明对起来，可以看到这个问题经过了复现、审查和版本发布。这能说明该规则近期有人维护，其他 Issue 的处理情况还要看各自的记录。[PR #30524](https://github.com/astral-sh/ruff/pull/30524)

11 月 26 日还有一项新提议，PR #30944 想减少终端输出诊断信息时重复查询显示样式的开销。这条 PR 在调研时仍处于开放状态，记录的是开发进展，是否进入某个版本还要看后续的发布说明。[PR #30944](https://github.com/astral-sh/ruff/pull/30944)
